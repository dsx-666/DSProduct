# 接口文档 v2.1 详细扩展版
版本：v2.1。基础契约更新：2026-09-29；代码、数据库与需求核对：2026-10-12。

基础地址：`http://localhost:8080`。支持格式：JSON。字符编码：UTF-8。

本文以原 v2.0 的权限、金额和统计口径为基础，并结合需求文本、`ecommerce_dataset` 导入脚本、当前 Spring Boot/MyBatis 代码补充经营增长、平台治理、消费者和 Agent 接口。每个接口都标记为“已实现、部分实现或规划”，避免把设计能力误认为现有能力。

本文包含当前后端接口基线和面向后续业务的目标契约。当前 Java 控制器可核对到认证 C0-C3、经营查询 A1-A9、初始化 A10、品牌 A11、人员 P1-P3、本人订单 U1-U2 中的实际路由；B、D、R、G 及本文新增的细分经营分析均为规划接口，不能视为已实现。数据库基础表为 `user`、`product`、`order`、`order_item`、`event`、`review`。成本、库存、曝光/点击归因和促销触达数据没有现成可信来源时，相关接口必须返回 `UNAVAILABLE` 或 `null`，不能伪造结论。

## 0. 公共约定
### 0.1 请求与响应格式
GET 参数放在 URL 查询字符串中，不使用 JSON 请求体。POST、PATCH 使用 JSON 请求体，`Content-Type: application/json; charset=UTF-8`。

所有接口的成功响应使用以下外层结构。后文“返回字段”表中以 `data.` 开头的字段均位于该结构内部。

| 返回字段 | 字段类型 | 说明 |
| --- | --- | --- |
| code | integer | 成功时为 `200`。不使用第二份文件中“0 正常、1 错误”的旧说明 |
| message | string | 响应说明，例如“响应成功”；前端不能依靠提示文字判断成功 |
| data | object / null | 具体业务数据。退出登录成功为 `null`，查询成功按各接口结构返回 |


```json
{
  "code": 200,
  "message": "响应成功",
  "data": null
}
```

以下是原文已经确定的 HTTP 错误状态。失败响应的业务 `code`、`data` 和校验详情格式尚未统一定义，不能把 HTTP 状态码与业务码必然相等当作既定事实。

| HTTP 状态 | 含义 | 典型场景 |
| --- | --- | --- |
| 400 | 请求参数不合法 | 日期无效、页码不合法、参数类型错误、传入不支持的参数 |
| 401 | 身份验证失败或会话失效 | 未登录、登录凭据错误、账户停用、会话被撤销 |
| 403 | 已识别身份但操作无权限 | 普通用户访问经营接口、品牌管理员访问人员接口、请求未授权品牌 |
| 404 | 资源不存在或不可见 | 订单不存在、品牌管理员查看其他品牌订单、普通用户查看他人订单 |
| 409 | 数据或并发冲突 | 邮箱重复、人员编辑版本过期 |


有效查询没有数据时返回成功响应和空数组、零计数，不用 404 表示空列表。不允许访问与没有数据必须分别处理。

### 0.2 身份和权限
| user.role | 中文名称 | 经营接口 A1-A11 | 人员接口 P1-P3 | 本人订单 U1-U2 |
| --- | --- | --- | --- | --- |
| NORMAL_USER | 普通用户 | 禁止，403 | 禁止，403 | 仅本人订单 |
| ADMIN | 品牌管理员 | 仅所属单个品牌 | 禁止，403 | 不使用此组接口 |
| SUPER_ADMIN | 超级管理员 | 全部品牌，可再筛选 | 允许 | 不使用此组接口 |


1. 一个管理员最多负责一个品牌，同一品牌可以分配给多个管理员。拟由 `user.managed_brand` 保存单品牌归属，该字段尚待审核创建。
2. 管理员没有绑定品牌，或绑定品牌已经不存在时，数据范围为空，绝不能自动解释为全部品牌。
3. 真实角色只有 `NORMAL_USER`、`ADMIN`、`SUPER_ADMIN`。`user.user_type` 中的 `NEW_USER/OLD_USER` 是历史标签，不是权限角色。
4. 身份来自服务端会话。客户端不能通过 `role`、`userId`、`allowedBrands`、`scope` 声明当前身份。人员管理接口中的同名业务字段只表示待编辑对象，不授予调用者权限。
5. 列表、详情和写操作都必须鉴权。角色、品牌、停用状态改变后，旧会话立即撤销或重新解析权限，不能永久使用登录时缓存的旧品牌。

### 0.3 公共数据类型
| 类型或字段 | 规则 |
| --- | --- |
| integer | JSON 整数。ID 使用数据库正整数，不使用 `O1001/P1001/U1001` 等前缀 |
| ID 精度 | 当前 ID 在 JavaScript 安全整数范围内；未来超出时需统一升级为字符串契约 |
| number 金额 | 单位为人民币元；逐条按分归一后累加，显示时保留两位小数 |
| number 比例 | 取值为 0-1，最多六位小数；例如 `0.5` 表示 50% |
| date | 字符串，格式 `YYYY-MM-DD` |
| datetime | 字符串，格式 `YYYY-MM-DD HH:mm:ss`，时区 `Asia/Shanghai`，不追加 UTC 的 `Z` |
| businessDate | 固定为 `2025-11-14`，不随电脑当前日期改变 |
| 默认经营区间 | `2025-10-16` 至 `2025-11-14`，共 30 天，包含起止日 |
| 已知可选日期 | 当前为 `2024-01-01` 至 `2025-11-14`，以 A10 元数据约定为准 |
| null | 未知、不适用或无权限，不可一律转成 0 或空字符串 |


原配置 `business.time=2025-11-15` 是前版指出的待对齐差异，本文不表示已经修改该配置。

订单真实状态为 `processing`（处理中）、`shipped`（已发货）、`completed`（已完成）、`cancelled`（已取消）、`returned`（已退货）。所有经营图表仅统计 `completed`；列表和详情可展示其他真实状态。

支付方式为 `银行卡支付`、`微信支付`、`支付宝支付`，缺失值 `null` 显示“未知”。币种固定人民币，不新增币种筛选。

### 0.4 公共经营筛选 F
A2-A8 接收以下参数，每个接口的参数表还会完整列出。A1、A10、A11 的选项不随经营筛选缩小；A9 不继承页面筛选，但始终执行身份权限。

| 参数 | 必选 | 位置 | 类型 | 说明 |
| --- | --- | --- | --- | --- |
| startTime | false | query | date | 含开始日。省略时取有效结束日前 29 天，早于最早可选日则截断 |
| endTime | false | query | date | 含结束日。省略时为 `2025-11-14` |
| category | false | query | string，重复键 | A1 返回的真实品类值，多选为 OR；省略表示不额外限制品类 |
| brand | false | query | string，重复键 | A11 返回的真实品牌值，多选为 OR；省略表示不额外缩小已有授权范围 |


日期规则：两日期均省略使用默认 30 天；空日期视为省略。非法日期、开始晚于结束、越过业务日或允许范围返回 400。快捷 7/30/90 天只转换为起止日期，不传 `lastDays`。

多选示例：

```latex
category=Electronics&category=Clothing&brand=NeoTech&brand=Orion
```

含空格和 `&` 的值应使用 `URLSearchParams` 编码，例如 `category=Home+%26+Kitchen`。参数去首尾空格、精确匹配、去重并排序。不接受空选项、逗号拼接、JSON 数组字符串、`brand[]`、`brands`、`category[]`、`all`、`null` 字面值；“全部”或清空选择应省略对应键。

筛选与权限规则：

1. `SUPER_ADMIN` 不传 brand 可看全部品牌；`ADMIN` 不传 brand 仍只看自己的品牌。
2. `ADMIN` 请求任何非所属品牌，包括多个 brand 中混入一个其他品牌，整次请求返回 403。
3. 同一参数的多个值为 OR，不同维度之间为 AND。品类与品牌必须命中同一条明细，不能分别由订单中的不同商品满足。
4. 执行顺序为身份范围、请求筛选、统计或分页。跨品牌订单在当前入选范围内按订单 ID 去重。
5. 缺明细订单只有 `SUPER_ADMIN` 且 category、brand 均省略时，才允许纳入经营统计和列表。
6. 显式列出全部品类或品牌仍属于商品明细筛选，会排除缺明细订单，不等同于省略参数。
7. A3-A8 不接受 `statuses`、`keyWord`、分页等额外参数。各接口只接收参数表中的键，不将整个页面状态发送给每个接口。

### 0.5 公共返回对象 filters 与 scope
A2-A8 均返回 filters 与 scope；A10、A11、C1、C2 等按各自说明返回 scope。U1 返回本人订单的 filters 与 scope，其默认日期和状态另见 U1。

| 返回字段 | 字段类型 | 说明 |
| --- | --- | --- |
| data.filters | object | 服务端实际采用的查询条件 |
| data.filters.startTime | date | 实际有效开始日 |
| data.filters.endTime | date | 实际有效结束日 |
| data.filters.category | string[] | 当前品类选择；`[]` 表示不额外限制 |
| data.filters.brand | string[] | 当前品牌选择；`[]` 不代表拥有全部品牌权限 |
| data.filters.statuses | string[] | A2 为实际状态；A3-A8 恒为 `["completed"]`；U1 为本人订单实际状态 |
| data.scope | object | 服务端确认的当前权限范围 |
| data.scope.mode | string | `ALL` 全部、`BRAND` 单品牌、`OWN` 本人 |
| data.scope.allowedBrands | string[] | ADMIN 为单品牌数组或空数组；其他角色为 `[]`，实际含义由 mode 决定 |
| data.scope.canViewFullOrder | boolean | SUPER_ADMIN 为 true；NORMAL_USER 仅本人完整订单为 true；ADMIN 为 false |
| data.scope.canManageUsers | boolean | 仅 SUPER_ADMIN 为 true |


### 0.6 订单金额与可见明细
历史成交金额使用 `order_item.item_price/item_total`；商品当前价只用于展示。每条 `item_total` 先归一到分精度，再累加。

| 字段 | SUPER_ADMIN 或订单本人 | ADMIN |
| --- | --- | --- |
| contentScope | `FULL` 或 `OWN` | `BRAND` |
| amount | 完整明细合计优先，无明细回退原订单金额 | null |
| originalAmount | 原 `order.total_amount` | null |
| itemsTotalAmount | 完整明细合计，无明细为 null | null |
| amountDifference | 明细合计减原金额，无明细为 null | null |
| hasAmountDifference | 差额绝对值大于 0.01 为 true，无明细为 null | null，不泄露跨品牌金额异常 |
| visibleAmount | 与 amount 相同 | 所属品牌可见明细合计 |
| visibleQuantity | 完整明细件数，无明细为 null | 所属品牌可见件数 |
| totalQuantity | 完整明细件数，无明细为 null | null |
| amountSource | 有明细 `ITEM_SUM`，无明细 `ORDER_TOTAL` | `BRAND_ITEMS` |
| matchedAmount，列表字段 | 当前可见范围内符合品类、品牌条件的金额；无商品筛选时等于 amount | 本品牌范围内继续符合品类、品牌条件的金额 |

### 0.7 统计口径
| 指标 | 规则 |
| --- | --- |
| 订单数 | 当前范围内按订单 ID 去重 |
| 成交商品数 N | 当前范围内累计销量大于 0 的不同商品数 |
| 热销商品数 | `ceil(N × 30%)`，N 为 0 时为 0 |
| 热销商品集合 | 按销量降序、销售额降序、商品 ID 升序，取前 `ceil(N × 30%)` 个；不扩大并列数量 |
| 热销范围 | 在整个当前授权及筛选范围计算，不分别按品类或品牌取 30% 后拼接 |
| TOP10 | 与热销集合独立；仅支持 amount 和 quantity 两种排序 |
| 新购买用户 | 注册日至固定业务日相差 0-29 天 |
| 老购买用户 | 注册日至固定业务日相差至少 30 天 |
| 用户异常 | 关联缺失、注册日缺失或非法、注册日晚于业务日等无法分类情况，单独统计 |


2025-10-16 注册为新用户，2025-10-15 注册为老用户。新老用户占比的分母是可分类购买用户数；异常占比的分母是全部去重购买用户数。A7 按购买用户去重，A8 按订单去重。

购买用户以 `order.user_id` 为准，不用 `order_item.user_id` 替代。用户当前角色及其后续调整不改变历史交易是否计入销售。历史订单早于注册日时，不据此推断用户生命周期，仍按约定统计完成交易。

A6 同一订单可以计入多个品类的订单数，不能把品类订单数相加作为 KPI 订单总数。TOP10 的商品金额之和也不代表全量销售额。

## 1. 获取数据库中种类数据（A1）
### 接口功能
返回当前用户有权限使用的实际品类值和中文名称，用于品类下拉选择。“全部品类”由前端提供，不伪造数据库品类，也不作为请求值发送。

### URL
`http://localhost:8080/api/categories`

### 支持格式
JSON，UTF-8。

### HTTP 请求方式
GET。

### 访问权限
ADMIN、SUPER_ADMIN。ADMIN 只获取所属品牌商品涉及的品类。

### 请求参数

## 12. 用户注册与登录（C0-C1）
### 接口功能
创建普通消费者账号。注册接口不允许客户端创建 ADMIN 或 SUPER_ADMIN，不接受 brand、role、managedBrand 或 accountStatus。当前 Java 实现将新用户角色设为 `NORMAL_USER`、用户类型设为 `NEW_USER`，注册日期取 `business.time` 配置，并立即返回 Bearer JWT。

### URL
`http://localhost:8080/api/auth/register`

### 支持格式
请求与响应均为 JSON，UTF-8。

### HTTP 请求方式
POST。

### 访问权限
无需已有登录会话。Spring Security 当前将该路径放行。

### 请求参数
| 参数 | 必选 | 位置 | 类型 | 说明 |
| --- | --- | --- | --- | --- |
| email | true | body | string | 邮箱格式校验，长度不超过数据库字段限制；必须唯一 |
| password | true | body | string | 6-20 位，至少包含大写字母、小写字母和数字 |
| confirmPassword | true | body | string | 必须与 password 完全一致 |
| userName | true | body | string | 用户显示名称；不作为登录键 |
| gender | false | body | string | 用户性别 |
| city | false | body | string | 用户城市 |


禁止传递或服务端忽略 `role`、`userType`、`brand`、`managedBrand`、`accountStatus` 和 `lockVersion`。密码只保存 BCrypt 哈希，任何响应不得返回明文或哈希。

### 返回字段
外层字段见 0.1。`data.user` 包含 `userId`、`userName`、`email`、`role`、`brand`、`createdAt`；`data.jwtToken` 为访问令牌；`data.scope` 按 0.5 返回 `OWN` 权限范围。当前实现的 DTO 属性存在 `UserId`、`CreateTime` 等大写命名，联调前必须统一为目标小驼峰 JSON。

### 接口参数示例
```http
POST /api/auth/register HTTP/1.1
Host: localhost:8080
Content-Type: application/json

```

成功响应中的 `data.user.role` 固定为 `NORMAL_USER`，`data.scope.mode` 固定为 `OWN`。邮箱已存在返回业务码 `20002`；密码不一致返回 `20004`；字段校验失败返回 `20001`。当前数据库中缺少邮箱的历史账号不能通过该接口覆盖更新，需由受控人员流程补全。

## 20. 品牌新老用户占比（按品牌购买次数）（B1）
### 接口功能
按品牌自创建以来的累计购买次数统计新老用户，不使用 startTime、endTime 或经营页面日期筛选。购买次数按用户在该品牌的有效完成订单数计算，同一订单内购买多个该品牌商品仍计一次。累计购买次数不超过 3 次的用户为新用户，超过 3 次的用户为老用户；该口径与按注册时间计算的新老客不同。

`http://localhost:8080/api/brand/customer-segments`

### 支持格式

### HTTP 请求方式
GET。

### 访问权限

### 请求参数
| 参数 | 必选 | 位置 | 类型 | 说明 |
| --- | --- | --- | --- | --- |
| brand | false | query | string | SUPER_ADMIN 可选的单个品牌值；ADMIN 不传此参数且固定使用自身品牌 |


不接收 startTime、endTime、category、page、num。ADMIN 传入 brand 参数返回 400；SUPER_ADMIN 指定多个 brand 或不存在的品牌返回 400。该接口始终从品牌首次产生交易起统计全量历史。

### 返回字段
| 返回字段 | 字段类型 | 说明 |
| --- | --- | --- |
| code / message | integer / string | 公共成功字段，见 0.1 |
| data.scope | object | 服务端确认的品牌授权范围 |

| data.scope.allowedBrands | string[] | ADMIN 为所属品牌或空数组；SUPER_ADMIN 的范围按 mode 解释 |

| data.period | string | 固定 `LIFETIME`，不受日期影响 |

| data.classifiedBuyerCount | integer | 新老用户占比的分母，即可分类购买用户数 |
| data.totalBuyerCount | integer | 全部去重购买用户数，含关联缺失或资料异常用户 |
| data.newBuyerRatio / oldBuyerRatio | number | 新、老用户占 classifiedBuyerCount 的比例；分母为 0 时返回 null |
| data.unclassifiedBuyerCount | integer | 无法关联用户或无法可靠计算累计购买次数的人数 |
| data.unclassifiedRatio | number | 异常人数占 totalBuyerCount 的比例；总人数为 0 时返回 null |
| data.generatedAt | datetime | 本次统计生成时间，Asia/Shanghai |

### 业务规则与异常情况
1. 只将 `completed` 订单计作有效购买；取消或退货订单不计入。订单状态发生改变时，需同步修正购买次数和用户分层。
2. 品牌购买次数按 `order.user_id` 和该品牌的订单去重，不按商品件数或 order_item 行数累计。跨品牌订单可分别计入涉及的各品牌，每品牌最多计一次。

4. 用户首次购买该品牌起计入新用户；累计完成购买次数第 1 至第 3 次为新用户，第 4 次起为老用户。无可追溯历史时不得将其默认标记为新用户，应纳入异常人数。
5. 未登录返回 401；NORMAL_USER 返回 403；ADMIN 请求无归属品牌或试图查询其他品牌返回 403；SUPER_ADMIN 请求不存在品牌返回 400。无交易记录时计数为 0、比例为 null。

### 业务规则与异常情况
1. 销售量、销售额和购买人数按 `completed` 订单计算，购买人数按用户去重。金额按 0.6 逐笔归一到分后累计。
2. 退货率、取消率须以订单数为分母，并使用订单生命周期内发生过的退货/取消事实；比例分母为 0 返回 null。若数据库没有状态历史，无法区分发生后又变更的状态，返回 null/`UNAVAILABLE`，不能仅用当前状态冒充历史发生率。
3. 复购率定义为范围内购买该商品至少两笔不同完成订单的去重用户数 / 范围内该商品去重购买用户数；分母为 0 返回 null。`FILTERED` 计算仅基于选定范围内订单，`ALL` 基于全历史。
4. 浏览量只能由可信的商品浏览事件累计；购物车和愿望清单字段按用户去重，并需明确事件去重/当前状态口径。缺少有效事件表或字段时返回 null 并标 `UNAVAILABLE`，不能返回 0。
5. 正常无匹配商品返回空 productList 和 total=0；非法排序、分页或参数返回 400；ADMIN 越权品牌返回 403。



## 22. 品牌商品经营详情（B3）
### 接口功能
查询单个商品的经营指标、商品评分、用户性别分布、注册时间新老客比例及首屏评价。选择 `range` 的规则与 B9 商品列表相同；其中商品新老客按账号注册日距固定业务日是否在 30 天内划分，不使用 B8 的品牌购买次数分层。

### URL
`http://localhost:8080/api/brand/products/{productId}`

### 支持格式
JSON，UTF-8。

### HTTP 请求方式
GET。

### 访问权限
ADMIN、SUPER_ADMIN。ADMIN 仅可查所属品牌商品。商品不存在与 ADMIN 无权查看的商品统一返回 404，防止探测其他品牌商品 ID。

### 请求参数
| 参数 | 必选 | 位置 | 类型 | 说明 |
| --- | --- | --- | --- | --- |
| productId | true | path | integer | 正整数商品 ID |
| range | true | query | string | `FILTERED` 或 `ALL`，规则同 B9 列表 |
| startTime | false | query | date | `FILTERED` 的含开始日 |
| endTime | false | query | date | `FILTERED` 的含结束日 |


不接受 brand、userId、category 或客户端权限参数。商品 ID 查询使用布隆过滤器拦截确定不存在的 ID；布隆过滤器命中仍须查数据库确认，禁止将误判直接当作商品存在或无权限。

### 返回字段
| 返回字段 | 字段类型 | 说明 |
| --- | --- | --- |
| code / message | integer / string | 公共成功字段 |
| data.filters / data.scope | object | 实际范围和服务端权限范围 |
| data.product | object | 商品基本信息、品牌、品类、当前价和商品表 rating |

| data.metrics.viewCount / cartUserCount / wishlistUserCount | integer / null | 浏览次数、购物车用户和愿望清单用户；无可信事件数据为 null |

| data.metricStatus | object | 每个可能不可用指标的状态，值为 `AVAILABLE` 或 `UNAVAILABLE` |
