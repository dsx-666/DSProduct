# C4 普通用户注册

版本：v2.1 增补；与原文第12节 C1-C3 登录会话接口配套。

## 接口与权限

`POST /api/auth/register`

完整地址：`http://localhost:8080/api/auth/register`

请求头：`Content-Type: application/json; charset=UTF-8`。允许未登录访问，只创建普通购买者 `NORMAL_USER`。管理员继续由超级管理员通过 P2 新增；超级管理员不能通过公开注册创建。

注册成功后**不自动登录**，前端返回登录表单并填入注册邮箱，由用户通过 C1 登录；不会返回 Cookie、token 或 csrfToken，也不替换调用者已有会话。

## 请求字段

| JSON 字段 | 必选 | 类型 | 校验规则 |
| --- | --- | --- | --- |
| name | 是 | string | 去首尾空格后1至40字符 |
| email | 是 | string | 去首尾空格、转小写；有效邮箱，最多255字符；使用现有唯一索引约束 |
| password | 是 | string | 8至64字符；不去除空格、不改变大小写 |
| confirmPassword | 是 | string | 必须与password完全一致；只校验，不保存 |

只接受上述四个字段。传入 `role`、`brand`、`managed_brand`、`brands`、`status`、`account_status`、`userId`、`signup_date`、`user_type`、`scope`、`version` 等额外字段，整次请求返回400/20001，不能通过注册指定权限。

```json
{
  "name": "演示购买者",
  "email": "newbuyer@example.test",
  "password": "Buyer123!",
  "confirmPassword": "Buyer123!"
}
```

## 服务端处理

1. 校验JSON对象、字段白名单、类型和长度；密码确认失败不创建任何记录。
2. 归一化邮箱，检查重复并使用 `user.email` 唯一索引保证并发注册只成功一次。唯一键冲突统一返回409，不能覆盖已有账号、重置密码或重新启用停用账号。
3. 由后端显式设置 `role=NORMAL_USER`、`managed_brand=null`、`account_status=ACTIVE`、`lock_version=0`，不能直接绑定请求体到用户实体。
4. `user_id` 由MySQL自增生成。`signup_date` 使用服务端当前 `Asia/Shanghai` 日期，不能使用看板固定业务日2025-11-14；`user_type` 可为null，统计继续依据注册日期。
5. 后端采用带盐的密码哈希保存到现有 `user.password`，算法及编码必须与C1一致、完整适配字段长度，禁止截断哈希。`confirmPassword`、原密码和哈希都不返回、不写入业务日志。
6. 插入在事务中完成，成功仅返回公开账号信息。普通用户登录后只访问U1/U2；新账号没有购买记录时返回成功空订单列表，不借用其他人的演示订单。

注册不依赖已有登录态，因此不能要求先取得登录后CSRF token。真实后端应校验允许的Origin、限制注册请求频率，拒绝不支持的Content-Type；此接口本身不建立或改变登录会话。本版未包含邮箱验证码/验证邮件，不代表已经证明邮箱归属。

## 成功响应

沿用项目约定：HTTP 200，业务 `code=200`。data.user结构与C1中的user一致；不返回C1的scope或csrfToken。

| data.user字段 | 类型 | 说明 |
| --- | --- | --- |
| userId | integer | 新用户ID |
| email / name | string | 归一化邮箱、姓名 |
| role / roleLabel | string | 固定NORMAL_USER / 普通用户 |
| brand | null | 普通用户没有管理品牌 |
| status | string | ACTIVE |
| version | integer | 新记录版本0 |
| createdAt | date | 对应signup_date，实际北京时间注册日 |

```json
{
  "code": 200,
  "message": "响应成功",
  "data": {
    "user": {
      "userId": 9005,
      "email": "newbuyer@example.test",
      "name": "演示购买者",
      "role": "NORMAL_USER",
      "roleLabel": "普通用户",
      "brand": null,
      "status": "ACTIVE",
      "version": 0,
      "createdAt": "2026-09-29"
    }
  }
}
```

上述ID和日期只是协议示例，不是写入真实数据库的结果。

## 失败响应

| 场景 | HTTP | code | message示例 |
| --- | ---: | ---: | --- |
| 非JSON对象、字段缺失、格式错误或越权字段 | 400 | 20001 | 注册只接收姓名、邮箱、密码和确认密码 |
| 两次密码不一致 | 400 | 20001 | 两次输入的密码不一致 |
| 邮箱已存在，含大小写变体和停用账号 | 409 | 409 | 邮箱已注册 |
| 非POST方法 | 405 | 405 | 请求方法不支持 |
| 来源校验失败 | 403 | 403 | 请求来源不受信任 |
| 请求频率超限 | 429 | 429 | 注册请求过于频繁，请稍后重试 |
| 数据库失败 | 500 | 20003 | 注册失败，请稍后重试 |

```json
{"code":409,"message":"邮箱已注册","data":null}
```

```json
{"code":20001,"message":"两次输入的密码不一致","data":null}
```

## 数据库与前端范围

注册复用已有 `user_id/name/email/password/signup_date/role/user_type`；普通用户的品牌、启停和版本字段沿用上一版待审核 `database-proposal.sql`，不因本次注册再新增表或验证码字段。该SQL仍未执行，后端上线需完成此前审核。本次不创建真实账号或修改真实数据库。

静态页登录处新增“注册账号”，可完成校验、重复邮箱提示、成功返回登录、新账号登录及空的“我的订单”。账号只保存在当前页面内存，刷新后消失；密码处理、来源检查、限流和持久化必须由真实后端实现，静态模拟不代表这些能力已经上线。

## 验收

- 匿名可注册；成功后仍未登录，必须调用C1。
- 姓名与邮箱去首尾空格，邮箱大小写归一；原密码保留原样。
- 重复邮箱和并发重复注册只创建一条；停用账号不可借注册恢复。
- 所有非法或越权字段请求无副作用，不能创建ADMIN/SUPER_ADMIN或自行分配品牌。
- 注册日按实际北京时间跨日计算，与固定业务日无关。
- 新账号只看本人空订单，经营接口和人员接口403，他人订单404。
- 失败后可修改并重试；密码确认只用于校验，不出现在响应中。
