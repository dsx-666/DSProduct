第一版定位为**面向运营人员的电商销售分析看板**：完整保留你最初的 F1—F8、A1—A5，再补充图表接口、订单详情和必要的数据处理规则。本次只确定业务逻辑，不修改代码或数据库。

新用户比例还有一个实际限制：全部9,340位用户中，任意连续30天内注册的人数最多为492人，无法仅靠选择固定日期达到30%。建议固定业务日为 **2025-11-14**，保留完整数据；“约30%新用户”作为后续演示数据整理目标。现有数据按此日期计算为418名新用户，占4.48%，展示时不能直接写成30%。日期与演示数据处理方案待你确认，下面其余规则可以先确定。

**统一的业务规则如下。**

| 项目 | 第一版规则 |
|---|---|
| 有效销售订单 | 只统计 `completed`。处理中、已发货、已取消、已退货订单不计入销售KPI、趋势、品类销售和商品排行。 |
| 订单金额 | 有明细时，统一以所有明细 `item_total` 的合计作为订单统计金额。保留原订单金额供核对，不在查询时修改数据库。 |
| 无明细订单 | 建议暂用原订单金额，并标记“缺少商品明细”。全部品类统计中归入“未归类”；选择具体品类时不纳入。避免把缺明细错误算成0元。 |
| 金额单位 | 统一为元，保留两位小数；页面可使用千分位，接口返回可计算的数值。 |
| 固定业务日 | 全系统使用同一个 `referenceDate`。默认日期、快捷范围、新老用户分类均以它为基准，不使用电脑当天日期。 |
| 新老用户 | 注册距固定业务日 **0—29天为新用户，满30天为老用户**；注册日在基准日之后的属于异常数据。基准日固定时分类保持不变，推进基准日后重新计算，不直接采用已有 `user_type`。 |
| 30%新用户目标 | 指演示数据初始化时的用户整体比例。F7统计的是筛选范围内的下单用户，其新用户比例应按实际结果计算，不强制保持30%。 |
| 热销商品 | 在当前日期、品类范围内，按已完成订单累计商品销量。设有销量的商品有N个，取销量排名前 `向上取整(N×30%)` 个；N为0时热销数为0。 |
| 排名并列 | 销量相同时按销售额降序，再按商品ID升序，保证结果稳定。热销商品数量固定按上述比例计算，不因并列扩大。 |

例如固定业务日为2025-11-14，2025-10-16至2025-11-14注册的为新用户，2025-10-15及以前注册的为老用户；默认“近30天”也显示2025-10-16至2025-11-14。

**原有前端功能全部保留，并细化为以下行为。**

| 编号 | 功能 | 具体业务逻辑                                                                                             |
|---|---|----------------------------------------------------------------------------------------------------|
| F1 | 看板首页 | 展示总销售额、总订单数、平均客单价、热销商品数。销售额按统一金额规则累计；订单数按订单ID去重；客单价＝销售额÷订单数，订单数为0时显示0。四项指标同时响应日期、品类筛选。             |
| F2 | 品类筛选 | 提供“全部品类”和数据库实际存在的10个品类，可映射为中文。选中品类后只累计匹配商品的金额、销量；订单数为包含这些商品的不同订单数。                                 |
| F3 | 时间筛选 | 支持起止日期和近7/30/90天(前端需要传递起止日期就行，近n天通过前端来处理)，均包含结束日，按下单时间筛选。结束日期不能晚于固定业务日，开始日期不能晚于结束日期。重置恢复全部品类、近30天。 |
| F4 | 销售趋势折线图 | 支持销售额、订单量切换，以及按天、周、月聚合。周从周一开始，无成交日期补0；首尾不完整的周或月只统计选中范围，不扩大查询区间。                                    |
| F5 | 品类销售柱状图 | 展示各品类销售额，默认降序；提示信息包含金额、销量、订单数、金额占比。选择具体品类后只显示该品类。跨品类订单分别参与各品类统计，因此品类订单数不能直接相加作为总订单数。               |
| F6 | 商品TOP10排行 | 横向柱状图支持销售额、销量排序，不足10个展示实际数量。销售额取成交明细小计，销量取购买件数之和；展示商品名称、品类、金额、销量和热销标记。TOP10与热销前30%分别计算。            |
| F7 | 用户行为饼图 | 提供“新老下单用户”和“支付方式”两个视图。前者对已完成订单的购买用户去重后，按固定业务日分类；后者按已完成订单数计算支付方式占比。同一用户多次下单，在用户占比中只算1人。             |
| F8 | 数据明细表格 | 一行一笔订单，展示订单号、商品摘要、统计金额、日期、状态。支持分页、订单号精确搜索和商品名模糊搜索；默认每页20条，按下单时间倒序，同时间按订单ID倒序。                      |

跨品类订单需要特别处理：一笔订单包含电子商品800元、服饰200元，选择服饰时，销售额为200元、订单数为1、客单价为200元。表格同时区分“整单金额1,000元”和“当前品类金额200元”。

第一版在以上功能基础上增加三项小扩展：点击订单打开详情；明细表支持状态筛选；展示固定业务日和数据异常提示。表格切换其他订单状态时，只改变表格内容，销售图表仍统计已完成订单。现有支付方式由导入脚本随机生成，支付饼图用于课程演示。

**接口完整覆盖原需求，并补齐新增功能；以下均为 `GET`。**

| 编号 | 接口                            | 请求条件与返回内容                                                 |
|---|-------------------------------|-----------------------------------------------------------|
| A1 | `/api/categories`             | 返回实际品类值、中文显示名称。“全部品类”为前端选项，不伪造数据库品类。                      |
| A2 | `/api/orders`                 | 支持种类筛选、起止日期、关键字、状态、页码、每页条数；返回订单列表、总记录数、页码、页大小。默认状态为已完成。   |
| A3 | `/api/orders/kpi`             | 返回总销售额、去重订单数、平均客单价、热销商品数，以及统计范围内缺明细订单数。                   |
| A4 | `/api/product/ranking`        | 支持 `metric=amount/quantity`；返回前10商品的名次、商品信息、销售额、销量、热销标记。  |
| A5 | `/api/orders/stats`           | 支持 `granularity=day/week/month`；每个时间段返回销售额、订单数，包含补0后的时间段。 |
| A6 | `/api/product/category-stats` | 返回各品类的销售额、销量、去重订单数和销售额占比。缺明细金额按约定计入“未归类”。                 |
| A7 | `/api/user/customer-stats`    | 返回新用户数、老用户数、有效购买用户总数、占比、无法分类的异常人数和固定业务日。                  |
| A8 | `/api/orders/payment-stats`   | 返回支付方式、订单数和占比；缺失支付方式归入“未知”，不静默丢弃。                         |
| A9 | `/api/orders/{orderId}`       | 返回订单信息、完整商品明细、原始总额、明细合计、最终统计金额及差额。                        |
| A10 | `/api/dashboard/meta`         | 返回固定业务日、数据可选日期范围、默认日期范围、币种及订单状态选项。                        |

A3—A8统一接收日期、品类条件；A2的关键字和额外状态筛选只作用于明细表。响应沿用项目已有的 `code/message/data` 结构，金额及比例均由后端统一计算。

页面操作和异常处理也纳入第一版：

- 首次进入读取默认日期及品类，然后加载四项KPI、图表和明细；点击查询后统一刷新，表格回到第一页。
- 快捷日期立即应用；自定义日期通过“查询”应用，避免用户只选完开始日期就触发请求。
- 无数据时KPI显示0，图表和表格显示空状态；接口失败显示错误及重试，不能伪装成没有销售。
- 快速切换筛选时，以最后一次条件为准，避免旧请求结果覆盖新结果。
- 日期无效、页码小于1等请求返回明确提示；第一版每页最多100条。
- 新老用户图以可分类的购买用户为分母，同时注明异常人数；不通过调整百分比凑出30%。

实现时分三步推进：**先完成统一统计规则、A1/A2/A3及筛选表格，再完成趋势、品类、排行和饼图，最后补订单详情与异常提示并核对数据一致性。** 验收重点是销售总额与完整趋势、完整品类汇总一致，跨品类订单不重复累计金额，新用户满30天准确转为老用户，热销前30%与TOP10互不混淆。暂不加入预测、推荐、复杂漏斗或微服务，先把这一版做成后续实习简历中能够解释清楚业务口径的完整项目。
